## 修复对应关系

| 问题 | 实现与验证 |
| --- | --- |
| R1 临时文件链接与目录权限 | 移除共享文件 mailbox，使用 Unix socket；目录 mobile 所有、0700，socket 0600；双方校验内核 peer UID；客户端不创建或截断命令文件。原生端删除蓝牙 setter。 |
| R2 超时与旧命令重放 | 每次连接一个请求；启动代次、请求有效期、有效期内重复 ID 检查；主队列执行前、设置副作用前重检有效性与连接。旧命令文件不再读取，断连写入返回结果未知。 |
| R3 同名创建的旧 ID | 日历按保存后的新 ID 查询并核对 source；ReminderKit 从新 change item 的真实 objectID/uuid 取 ID，准确读回该 ID，核对 list。Python 再核对 created_id 与来源。 |
| R4 活动正文监测 | 对比存在性、生命周期和 content；样本保留正文，独立哨兵区分首次观察与目标不存在。 |
| R5 删除查询失败 | 原生查找显式返回查询是否完成；读取失败只能 partial/unavailable，确认删除必须带 readback_complete。 |
| R6 双客户端覆盖 | 每连接独立应答，设备端串行执行；不存在共享临时文件或删除别的客户端结果的路径。 |
| R7 事件截断 | 按开始时间及 ID 排序，支持 limit/offset；返回 total、truncated、next_offset，未覆盖整个指定范围时不声明完整。 |
| R8 搜索权限失败 | 根目录失败返回 unavailable；子路径失败返回 partial，并保留有界错误和失败计数。 |
| R9 时间/备注读回 | 原生与 Python 均核对事件所属日历、标题、UTC 开始/结束和 notes；保留输入时间的小数部分。 |
| R10 搜索结果位置 | 每个匹配返回 relative_path，同名文件可准确定位；继续不跟随目录符号链接。 |

## 安装中发现并处理的两次失败

第一版注入进程中的 Foundation 字典读取触发 runtime trap，自动回退后改为 C 通信，使用 C 字符串、系统 build 查询及有界帧解析。

第二版过早释放 BluetoothManager，异步回调随后访问已释放对象，触发安全模式。该释放由本轮修复引入，已撤销；最终版只初始化一次并持有管理器至进程结束。RadioPreferences 采用同样的生命周期。此次健康检查也扩展为覆盖全部读接口及延迟观察。

两次失败均恢复了备份并清除了本次新增的安全模式状态。最终安装通过了上述检查。这里记录的是有界观察结果，不将其表述为长期稳定性保证。私有接口仍限于已验证的 iOS 16.1.1 / 20B101。

## 升级与恢复

Python 入口与原生 helper 需一起升级；日历与提醒 helper 保持安装在 `/var/jb/usr/local/bin/`。SpringBoard shim 的新协议与旧文件 mailbox 不兼容，缺少新 socket 时客户端明确返回 unavailable。

安装器先编译签名，再备份旧 dylib/plist、设置受限 IPC 目录并替换文件；只有显式 `--respring` 才重载桌面。`--build-only` 只构建。此次设备部署另使用了保留在仓库外的恢复守护程序，失败会恢复源码与原生文件；不把含设备路径的部署脚本提交到公开仓库。
