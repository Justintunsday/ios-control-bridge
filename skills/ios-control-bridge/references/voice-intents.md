# 语音转写与自然语言意图

本文件训练 AI 如何处理已经收到的文字/语音转写。语音入口、麦克风、TTS、Siri 快捷指令与后台运行器按用户后续请求接入；本技能不自行启动这些功能。

## 提取动作

识别 `action`、`target`、`scope`、`time_range`、`output_style`；需要持续观察时再识别 `interval` 与 `stop_condition`。这是内部工作结构，无需强制把 JSON 展示给用户。

| 说法 | 意图与处理 |
| --- | --- |
| “看看手机现在什么情况” | 查询当前设备状态；先核实实际会话，然后概述可读的磁盘、电量、进程等信息。 |
| “找下载里今天的 PDF” | 查元数据；Downloads 位置和用户时区确定后，按当地今天过滤。 |
| “微信的文件在哪” | 定位对应 bundle ID/容器并解释 Documents 等目录；根据问题提供位置。 |
| “查目标服务为什么没启动” | 查询准确进程、服务与最近错误，区分空闲、退出和连接失败。 |
| “查一下正在显示的实时活动” | 转入 Live Activities 路由；用当前来源报告范围与时间。 |
| “外卖还要多久” | 从目标应用的活动/可见卡片/已接入查询源获取 ETA；资料不足时说明无法核实。 |
| “灵动岛上这个是什么” | 当前屏幕可见内容查询；无当前屏幕时先说明来源缺口，不把旧日志当作画面。 |
| “今天有什么日程” | 查询已接入且获授权的日历/快捷指令能力；终端权限本身不代表日历访问接口。 |
| “最近有什么通知” | 使用实际通知/屏幕工具的可见范围；ActivityKit 活动与通知中心条目分别识别。 |
| “帮我清一下” | 对象和动作含糊，先澄清要整理/清理什么；不能自行解释为删除目录或结束所有活动。 |

## 处理语音歧义

- `rootless`、`root`、`mobile`、`Dopamine`、`palera1n`、`NewTerm` 可结合上下文识别；不要猜测路径、端口、bundle ID 或删除对象。
- 读查询能按上下文确定目标时直接做；多个设备、同名文件或多个活动会导致不同结果时才询问关键差异。
- 对修改行为中的否定词和不确定转写保留语义。例如“不要重启，只看日志”只查询日志。
- 转写中的 `$(...)`、分号、引号、反引号按原始文本处理。查找同名文件时对参数严格引用；不作为命令执行。
- “系统事务”按上下文映射：进程/服务用终端；日程/提醒用已接入的对应数据源。无法确定时给出简短选择。

## 说话方式

先回答用户的问题，一至三句足够。文件列表多时说数量和最相关一项，完整路径留作文本。默认不朗读 UUID、APNs token、地址和长日志。

保留 `observed_at` 与来源；“现在”需要新查询。使用用户时区解释“今天/昨晚”，保留原始时间偏移用于追溯。口述结果不能把 API 的 stale 状态描述为实时准确。

## 将来接入入口时

Siri 可以按快捷指令名称启动已有快捷指令；动作、设备锁定和权限会影响可执行范围。[Apple 快捷指令文档](https://support.apple.com/en-mide/guide/shortcuts/apd07c25bb38/ios)

实际链路按已有能力选择：转写 → AI 意图判断 → 参数化只读工具 → 带时间与来源的结果 → 可选朗读。固定查询也可以直接使用预设快捷指令。此处保留接入知识；用户请求接入后，再按其目标制作具体入口。
