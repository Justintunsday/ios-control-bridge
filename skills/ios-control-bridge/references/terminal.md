# 终端与系统事务查询

## 会话和连接

优先使用已有的 NewTerm/SSH/设备工具。先核实命令运行位置；电脑上的 `uname`、`ps`、`df` 只能描述电脑。终端应用名不代表连接目标或当前用户。

SSH 使用用户已经提供的目标和现有凭据管理方式，保留主机密钥校验。不读取无关凭据、不写入默认密码、不为查询任务开放端口、建立公网映射或修改 sshd。首次主机密钥应通过可信渠道核对；主机身份变化时先定位原因。

参数传递优先使用工具提供的参数数组。经过 SSH 时还存在远端 shell 解析层，必须分别处理引用；JSON 编码不能替代 shell 引用。不要把自然语言或搜索词直接拼入远端命令。

## 查询工具选择

下表是命令形状；先通过 `command -v` 和工具帮助确认可用性与参数。给查询设置合理运行时间和输出上限，保留退出码与 stderr。

| 用户目标 | 查询形状与解释 |
| --- | --- |
| 环境、权限 | `id`、`uname -srm`、`sysctl -n hw.machine`；版本从 SystemVersion.plist 或可用的 `sw_vers` 获取。 |
| 文件权限 | `ls -ld '/absolute/path'`，文件信息用当前 `stat` 支持的格式；BSD `stat -f` 与 GNU `stat -c` 分别处理。 |
| 查 PDF | 若支持对应参数：`find '/var/mobile/Documents' -xdev -maxdepth 4 -type f -iname '*.pdf' -print`。相关应用目录需另行定位。 |
| 大文件/空间 | `df -k '/var/mobile'`；在已确认的小范围目录用 `du -k`，按实际支持的排序工具处理。不要以文件大小之和代替卷可用空间。 |
| 进程 | 支持时用 `ps -axo pid,ppid,pcpu,pmem,stat,comm`。优先显示命令名；完整参数可能包含令牌。CPU/内存字段不可用时说明缺失。 |
| 服务 | `launchctl list` 或经确认可用的 `launchctl print system/实际服务标签`、`launchctl print gui/实际UID/实际服务标签`。当前连接可能只能看到部分域。 |
| 已安装包 | `dpkg --print-architecture`、`dpkg-query -W`、`dpkg-query -L '已核实的包名'`；这些查询不需要 `apt update`。 |
| 系统日志 | 探测到可用 `log` 后使用有限时间窗、明确进程/subsystem 的 `log show`，保留原始时间与来源；不能默认越狱工具含完整 macOS `log` 实现。 |
| 崩溃信息 | 在目标诊断目录按应用名/时间定位报告，先读摘要及与故障相关的片段。 |
| 电池/内存 | 可用时用 `vm_stat` 和经过字段过滤的 `ioreg -r -c AppleSmartBattery`。保留原始键、单位和采样时间；未核实字段语义时不计算百分比/摄氏度。 |

限制范围时优先由运行器约束时间与输出。管道默认可能只返回最后一个命令的退出码；不要用 `find ... | head` 的成功掩盖 `find` 的权限或 I/O 错误，也不要用 `2>/dev/null` 把错误包装成空结果。

## 常见误判

- iOS 使用 launchd，通常没有 Linux `/proc`、`/sys`、`systemctl`、`journalctl`；需要按 Darwin 工具处理。
- 不同工具包可能提供 GNU、BSD 或精简实现。`--help`、`-maxdepth`、`-printf`、`readlink -f` 等不是统一保证。
- `launchctl list` 的退出状态列描述上次退出结果；PID 为 `-` 不直接说明故障，按需启动的服务可以空闲。
- 在当前 launchd 域里查不到服务，不代表 system 或其他用户域中不存在。
- 进程名称相同不保证是同一个服务。关联 PID、路径、标签、启动时间后再解释。
- `which` 的输出、某个目录存在、提示符中出现 `root` 都不足以代替实际权限和路径探测。

## 修改请求

维护请求先确认实际路径/包/服务、当前状态和预期结果。可恢复配置修改先保留备份或差异；重启服务先确认精确标签、影响与恢复方式。用户已有明确授权时继续完成并验证，不为每条普通命令重复询问。

当对象不明确或动作会造成当前授权未覆盖的数据删除、重启/注销、包安装卸载或全局配置变化时，先准备具体可审查的范围，再补齐必要授权。“查一下”“看看”“怎么做”保持对应的查询或说明范围。

查询不到时可给出一个能解决当前缺口的下一步；命令缺失时先采用已有替代工具，不自动安装整套工具链。
